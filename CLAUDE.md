# gstack routing

Use the matching gstack skill for the task rather than improvising a workflow:

- `/investigate` for bugs, regressions, errors, or root-cause analysis.
- `/qa` to test and fix a feature; `/qa-only` for a report without changes.
- `/review` for a pre-landing code review; `/cso` for a security audit.
- `/plan-ceo-review`, `/plan-eng-review`, `/plan-design-review`, or `/plan-devex-review` for the corresponding plan review.
- `/design-review` for visual QA; `/browse` for real-browser inspection and interaction.
- `/ship` to prepare and publish a change; `/land-and-deploy` to merge and verify deployment.
- `/context-save` and `/context-restore` for gstack session continuity.

Keep project-specific rules and the user's requested scope authoritative. Verify results with fresh evidence before reporting completion.
